# DevLane

面向研发团队的 AI 并行开发工作台。从 Jira 看板进，到 PR 出，中间每一步都看得见。

## 当前阶段：M0

已完成：

- **需求与设计文档** (`docs/`)
  - `01-需求分析.md`：从参考图拆解出产品核心（并行、可观测、可接管），用户痛点与成功指标
  - `02-PRD.md`：对象模型、用户故事、功能需求、状态机、门禁、交接、验证
  - `03-技术设计方案.md`：架构、技术选型、事件溯源、Jira 连接器、沙箱与策略引擎、数据模型、API、安全、测试
  - `04-落地缺口分析.md`：阻塞项清单（需要你提供的）、设计缺口、自动推进的边界

- **核心共享包** (`packages/`)
  - `event-schema`：19 类事件类型定义、payload 校验、基于 SHA-256 的哈希链
  - `adf`：Atlassian 文档格式转 Markdown，覆盖段落、标题、列表、代码块、引用、表格
  - `readiness`：就绪评分（验收标准 30 分、复现步骤 30 分、影响范围 20 分、优先级 / 截止 / 负责人各 10/5/5 分），阈值 70 分

- **测试与工具链**
  - 32 个测试用例覆盖哈希链校验、ADF 边界情况、就绪评分规则
  - TypeScript 7.0 严格模式，Vitest 5.0
  - npm workspaces，零依赖（运行时），零漏洞

## 快速验证

```bash
npm install
npm run typecheck  # 类型检查
npm test           # 运行全部测试
```

## 阻塞项（需要你提供）

见 `docs/04-落地缺口分析.md` §2，核心是：

1. Jira 站点类型（Cloud / Data Center）与测试凭据
2. 代码托管平台（默认 GitHub）
3. 模型 API 密钥与预算上限
4. Docker 主机（本机未安装，开发期用本地执行器）
5. Jira 工作流状态名（用于回写映射）

## 下一步

M1 阶段：事件服务（SQLite 先行）、状态机、策略引擎、调度器，不依赖上述阻塞项。

提供上述阻塞项后：Jira 连接器联调 → 模型网关接入 → 真实执行器。

## 技术栈

- Node.js 22 + TypeScript 7 + Vitest 5
- 前端：React（M1+）
- 后端：Fastify（M1+）
- 数据库：PostgreSQL（生产）/ SQLite（开发）
- 沙箱：Docker（生产）/ 本地进程（开发）
