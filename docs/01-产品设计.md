# DevLane 产品设计（程序员个人版）

| 项 | 内容 |
| --- | --- |
| 版本 | 0.2 |
| 日期 | 2026-10-28 |
| 取代 | `docs/archive-团队版/`（面向研发团队的设计，代码见标签 `v0.1-team-demo`） |

## 1. 定位

**给一个程序员，在自己电脑上，日常修缺陷、做需求用的工作台。**

你描述任务（或从 Jira 选一个），DevLane 为它单独建一个 git worktree 和分支，让本机的 Claude Code 在里面干活。你看着它的过程，审阅 diff，跑测试，满意了就提交、推送、开 PR；不满意就追问或丢弃。你的当前工作目录始终不被碰。

### 与团队版的区别

| | 团队版（已废弃） | 个人版 |
| --- | --- | --- |
| 使用者 | 研发团队、项目经理 | 你自己 |
| 运行位置 | 服务器 | 本机，只监听 127.0.0.1 |
| 入口 | 需求池 + 就绪评分 + 门禁流程 | 直接建任务，或从 Jira 列表选 |
| 执行 | 模拟 | 真实的 Claude Code，改真实的代码 |
| 认证 | 共享口令 | 无（本机单用户），靠主机与来源校验防止网页偷调 |

### 不做什么

多用户、权限体系、云端部署、自建模型调用、代码托管平台的完整管理、需求评审流程、看板统计报表。

## 2. 核心流程

```
选项目 ─▶ 描述任务(或选 Jira) ─▶ 建 worktree+分支 ─▶ Claude 工作 ─▶ 你审阅 ─▶ 提交 ─▶ 推送+PR
                                         │                  │          │
                                         │                  ├─ 被拦截的操作 ─▶ 你决定允许/忽略 ─▶ 继续
                                         │                  └─ 你追问 ───────────────────────────▶ 继续
                                         └─ 不满意：丢弃（删除 worktree 和分支）
```

一个任务从头到尾的状态：

| 状态 | 含义 | 你能做什么 |
| --- | --- | --- |
| 排队 | 并发已满，等位 | 丢弃 |
| 运行中 | Claude 正在工作 | 停止 |
| 待你决定 | Claude 想做的某些操作被拦截 | 允许后继续、忽略、追问 |
| 待审阅 | Claude 完成一轮 | 看 diff、跑测试、追问、提交、丢弃 |
| 已停止 | 你停止，或服务重启时被中断 | 追问（继续）、提交、丢弃 |
| 失败 | Claude 报错退出 | 追问（重试）、丢弃 |
| 已提交 | 变更已提交到任务分支 | 推送并开 PR、继续追问、丢弃 |
| 已开 PR | 已推送且创建了 PR | 丢弃（清理 worktree） |
| 已丢弃 | worktree 与分支已删除 | 无 |

## 3. 功能

### 3.1 项目

- **手动输入本地项目路径**，点「检查」即显示：是否 git 仓库、仓库根目录、当前分支、推荐基线分支、是否有未提交改动、是否有远程。
- 每个项目配置：名称、基线分支、测试命令（如 `npm test`）、额外允许 Claude 执行的命令、是否把主仓库的 `node_modules` 链接进 worktree（省去每个任务重新安装）。
- 可编辑、可删除（有未结束的任务时不能删除）。

### 3.2 任务

- 新建：选项目、类型（缺陷 / 需求）、标题、描述，可关联 Jira 编号。创建后立即开始，或并发已满时排队。
- 提示词由类型决定：
  - 缺陷：先定位根因并尽量写能复现的失败测试，再最小化修复，用测试命令验证。
  - 需求：先理清做法，实现并补测试，用测试命令验证。
  - 两者都明确要求：**不要 git commit / push**，由你在界面里提交。
- 过程可见：Claude 的文字、读了哪些文件、改了什么、跑了什么命令及结果，按时间线显示，实时更新。
- 追问：随时对已有会话发新指令，沿用同一会话上下文（`--resume`）。
- 费用：每个任务累计显示花费，单次运行有预算上限（默认 3 美元，可改）。

### 3.3 审阅与交付

- **变更**：文件列表（增删行数），逐文件 diff，新增文件也显示。
- **测试**：一键在 worktree 里运行项目的测试命令，显示输出与耗时。
- **提交**：填写提交说明（默认带 Jira 编号和标题），提交到任务分支。
- **推送并开 PR**：`git push -u origin <分支>`，再用 `gh pr create`。
- **丢弃**：删除 worktree 和分支，不可恢复，需确认。
- **用编辑器打开**：在 VS Code 中打开任务的 worktree，自己动手改。

### 3.4 Jira

- 设置里填站点地址、邮箱、API Token，点「测试连接」。
- Jira 页：默认列出「指派给我、未完成」的 issue，可切换范围，可按关键字或编号搜索，高级模式可直接写 JQL。
- 点一条看详情（描述转为 Markdown、最近评论），一键「用它建任务」，标题、描述、类型、编号自动带入。
- 只读：不会修改 Jira。

### 3.5 设置

Jira 连接；Claude 可执行文件路径（默认自动查找）、模型（留空用 Claude 自己的默认）、单次运行预算、同时运行任务数（默认 2）、编辑器命令（默认 `code`）。

## 4. 安全模型

这是一个能在你电脑上运行命令的本地服务，威胁主要来自三处：

1. **你访问的其他网页偷偷调用本地接口。** 只监听 127.0.0.1；校验 `Host`（防 DNS 重绑定）；写操作必须带自定义请求头并校验 `Origin`；不发任何跨域放行头。
2. **Claude 做了你不想让它做的事。**
   - 每个任务都在独立 worktree 里，主工作目录不动。
   - 通过 `--settings` 文件给出明确的允许与禁止清单（命令行里不拼任何用户输入）。
   - 允许：读、搜索、在 worktree 内编辑、测试命令、只读的 git 命令。
   - 永久禁止：`git push`、`git commit`、`git reset`、`git checkout` / `switch`、`git clean`、`rebase`、`merge`、`rm -rf`、`sudo`。
   - 其他需要审批的操作（安装依赖、联网等）被自动拒绝并记录，由你决定是否允许（精确到那一条命令，或同类前缀；永久禁止的不能被放行）。
3. **凭据泄露。** Jira Token 只存在本机 `~/.devlane/settings.json`，接口永不返回完整 Token，日志不记录。

不覆盖的风险：Claude 在被允许的测试命令里间接运行恶意代码（例如仓库内的测试脚本）。运行不可信仓库的任务前请自行评估。

## 5. 架构

```
浏览器 (React)  ◀── HTTP + SSE ──▶  本地服务 (Node + Fastify, 127.0.0.1)
                                      ├─ 项目 / 任务 / 设置存储 (JSON, ~/.devlane)
                                      ├─ git 操作 (worktree、diff、commit、push)
                                      ├─ Claude 适配器 (子进程, stream-json 解析)
                                      ├─ 任务调度 (并发上限、排队、重启恢复)
                                      └─ Jira 客户端 (REST v3, 只读)
```

- 数据目录 `~/.devlane/`：`state.json`（项目、任务、设置）、`tasks/<id>/`（时间线日志 `log.jsonl`、`settings.json`）、`worktrees/`（所有任务的工作目录）。
- Claude 适配器是可替换的接口，后续可加 `kiro-cli`、`codex`。
- 一次运行 = 一次 `claude -p` 子进程，提示词走标准输入。首次用 `--session-id`，之后用 `--resume`。

## 6. 验收标准

1. 在本机一个真实仓库里，描述一个缺陷，DevLane 能产出正确的修复 diff，并且主工作目录没有任何改动。
2. 被拦截的操作显示在界面里，允许后 Claude 能继续并完成。
3. 提交后任务分支上有一个包含变更的提交；丢弃后 worktree 与分支都不存在。
4. 手动输入的项目路径被校验：不存在、不是目录、不是 git 仓库时给出明确提示。
5. Jira 列表在填写凭据后可显示、搜索、查看详情，并能带入新任务。（需要真实凭据联调，未联调前仅有夹具测试。）
6. 浏览器之外的来源（错误的 Host 或 Origin）调用写接口会被拒绝。
7. 服务重启后，运行中的任务变为「已停止」，可追问继续。
