# DevLane 使用手册

| 项 | 内容 |
| --- | --- |
| 适用版本 | 0.2.0（程序员个人版） |
| 运行方式 | 本机运行，浏览器访问 http://127.0.0.1:7788 |

## 1. 它是什么

你描述一个缺陷或需求，DevLane 为它单独建一个 git 工作区和分支，让你电脑上的 Claude Code 在里面干活。你看过程、审 diff、跑测试，满意了再提交、推送、开 PR。

**核心保证：你正在用的工作目录、你当前的分支、你没提交的改动，都不会被碰。** 所有改动发生在独立的副本里：默认在 `~/.devlane/worktrees/`；如果项目和 `~/.devlane` 不在同一个盘符（例如项目在 D 盘、用户目录在 C 盘），副本会放在项目旁边的 `.devlane-worktrees` 目录（如 `D:\.devlane-worktrees`），原因见第 11 节。

## 2. 启动

```powershell
cd d:\dev面板\devlane
npm install        # 第一次
npm run build      # 第一次，或改了代码之后
npm start          # 启动并打开浏览器
```

需要 Node 20+、git、已登录的 `claude` 命令。要开 PR 还需要 `gh`（先 `gh auth login`）。关掉终端窗口，服务就停了，正在运行的任务会被中断（下次启动后可以点「继续」）。

## 3. 第一次使用（5 分钟）

1. 打开「设置」，看「环境检查」里 claude、git 是不是绿点。
2. 打开「项目」→「添加项目」，输入仓库的**完整路径**（例如 `D:\code\my-app`），点「检查」。
   - 会显示仓库根目录、当前分支、推荐的基线分支、有没有远程、主目录有没有未提交改动。
   - 填**测试命令**（如 `npm test`）。这很重要：Claude 会用它验证，你也能一键运行。
   - 点「添加项目」。
3. 回到「任务」→「新任务」，选项目，选「缺陷修复」或「需求开发」，写标题和描述，点「创建并开始」。
4. 在「过程」页看 Claude 工作。完成后状态变成「待审阅」。
5. 看「变更」里的 diff，在「测试」里运行测试，在「交付」里提交。

## 4. 怎么写任务描述

Claude 只能看到你写的内容和仓库里的代码，描述越具体，结果越准。

- **缺陷**：怎么复现、期望什么、实际是什么、报错信息或日志、你怀疑的位置。
- **需求**：要做什么、验收标准、涉及的模块或文件、需要遵守的约定、不要动什么。

## 5. 任务的状态

| 状态 | 含义 | 你能做什么 |
| --- | --- | --- |
| 排队中 | 同时运行的任务数已满（默认 2） | 取消排队 |
| 运行中 | Claude 正在工作 | 停止 |
| 待你决定 | Claude 想做的某些操作被拦截了 | 放行、不放行、追问 |
| 待审阅 | Claude 完成了一轮 | 看变更、测试、追问、提交、丢弃 |
| 已停止 | 你停止了它，或服务重启过 | 继续、追问、提交、丢弃 |
| 失败 | Claude 报错退出（超预算、未登录等） | 看错误原因，继续、丢弃 |
| 已提交 | 变更已提交到任务分支 | 推送并开 PR、继续追问 |
| 已开 PR | 已推送并创建了 PR | 丢弃（清理本地工作区） |
| 已丢弃 | 工作区和分支已删除 | 无 |

任务列表里，「待你决定」和「失败」排在最前面，左侧导航「任务」旁的数字是等你处理的任务数。

## 6. 被拦截的操作

Claude 默认可以：读代码、搜索、在工作区里改文件、运行你配置的测试命令、只读的 git 命令（status、diff、log、show 等）。

其他命令（安装依赖、联网、跑别的脚本）会被自动拒绝，并出现在任务顶部的黄色面板里：

- **只放行选中的这几条并继续**：只放行那一条完全相同的命令。
- **放行同类命令并继续**：放行同前缀的命令，例如放行 `npm install lodash` 会放行所有 `npm install …`。
- **都不放行，直接审阅**：保持现状，去看 Claude 已经做完的部分。

放行只对**这一个任务**有效，之后 Claude 带着新权限接着做。

**永远不能放行**（面板里会标「不能放行」）：`git commit / push / reset / checkout / clean / rebase / merge` 等改历史和提交的命令、`rm` 等删除命令、`sudo`、`curl`、`gh`、含 `&& | ;` 的复合命令，以及越出工作区的写文件。提交和推送请自己在「交付」页做。

经验上，常见的需要放行的是 `npm install`、`pip install`、`npm run build` 这类。经常用到的可以写进项目的「额外允许的命令」，就不会每次被拦。

## 7. 审阅与交付

**过程**：Claude 说的话、读了什么文件、改了什么、跑了什么命令。点一行工具调用可以展开输出，红色表示失败。

**变更**：左边文件列表（新增 / 修改 / 删除，增删行数），右边逐文件 diff。每次 Claude 完成一轮自动刷新。

**测试**：在这个任务的工作区里运行项目的测试命令。运行中会实时显示输出，可以随时点「停止测试」，它会连同测试命令启动的所有子进程一起终止（状态显示「已停止」）；超过 15 分钟会自动终止。停止后可以点「重新运行」。丢弃任务时如果测试还在跑，也会先终止它。

**交付**：
1. **提交**：写提交说明（默认带上 Jira 编号和标题），提交到任务分支，不会动基线分支。
2. **推送并创建 PR**：执行 `git push -u origin <任务分支>`，再用 `gh pr create`。需要仓库有名为 `origin` 的远程，且已安装并登录 `gh`。提交之后又有新改动时，需要先再提交一次。
3. **用编辑器打开工作区**：用设置里的编辑器命令（默认 `code`）打开，自己动手改。
| Agent 提示模板 | 按 bug/feature 自定义初始 Agent 提示；留空用内置默认；与 Jira 独立不回写 |
4. **丢弃这个任务**：删除工作区和分支，未提交的改动无法找回。已推送的远程分支和 PR 不受影响。

**追问**：页面底部的输入框（Ctrl+Enter 发送）。沿用同一个 Claude 会话，它记得之前做过什么。例如：「再补一个边界测试」「这里不要改接口」「解释一下为什么这样改」。

## 8. 从 Jira 选任务

1. 「设置」→「Jira」，填：
   - 站点地址，例如 `https://house730.atlassian.net`
   - 登录邮箱
   - API Token（到 [id.atlassian.com → 安全 → 创建 API 令牌](https://id.atlassian.com/manage-profile/security/api-tokens) 创建）
2. 点「保存并测试连接」，成功会显示你的用户名。
3. 打开「Jira」页：
   - 默认列出「指派给我、未完成」。可切换为「我报告的」「最近 30 天有更新」。
   - 输入编号（`ABC-123`）或关键字回车搜索。
   - 点「写 JQL」可以直接写 JQL 查询。
   - 点一条 issue 看描述和最近评论。
   - **「用它创建任务」**：标题、描述（含 Jira 链接和评论）、类型（Bug 对应缺陷，其他对应需求）自动带入，选好项目就能开始。
4. 在设置里可以给一个「默认 JQL」，不选任何筛选时就用它。

DevLane 对 Jira 只读，不会改任何 issue。Token 只存在本机，界面上永远不显示。

## 9. 设置项

| 设置 | 说明 |
| --- | --- |
| claude 命令路径 | 留空自动查找。找不到时填完整路径 |
| 模型 | 留空用 Claude 自己的默认设置（包括你在 `~/.claude/settings.json` 里的） |
| 单次运行预算上限 | 默认 3 美元。超过会自动停止，调高后点「继续」 |
| 同时运行的任务数 | 默认 2，最大 8。每个运行中的任务都在花钱 |
| 编辑器命令 | 默认 `code` |

每个项目还有：基线分支、测试命令、额外允许的命令、是否链接 `node_modules`。

**关于 node_modules**：开启后，任务工作区里会放一个指向主仓库 `node_modules` 的链接，Claude 和测试可以直接用已安装的依赖，不用重新安装。仅在它已被 `.gitignore` 忽略时生效。丢弃任务时只会移除链接，不会动主仓库的依赖。

## 10. 费用

每个任务显示累计花费（来自 claude 的统计）。几点经验：

- 描述越具体，Claude 绕的弯越少，花费越低。
- 一个简单缺陷通常几毛到一美元；你的 claude 环境如果每轮都带很大的上下文，会更高。
- 预算上限是**每一次运行**的，不是整个任务的总额。多次追问会累计。
- 同时运行的任务越多，花费累积越快。

## 11. 常见问题

**创建任务时报「这个文件夹不是 git 仓库」**
路径要指向仓库内（根目录或子目录都行）。DevLane 会自动找到仓库根目录。

**我主目录里有没提交的改动，任务会包含它们吗？**
不会。任务从基线分支**已提交**的内容拉出。需要的话先提交或另开分支。

**任务一直「排队中」**
同时运行的任务数已满，等前面的完成，或在设置里调大。

**Claude 报「not logged in」或认证相关错误**
在终端里先运行 `claude` 完成登录，再回来点「继续」。

**找不到 claude 命令**
「设置」里填完整路径，Volta 安装的类似 `C:\Users\你\AppData\Local\Volta\bin\claude.cmd`。

**提交失败，提示没有 user.name / user.email**
在仓库里配置 git 身份：`git config user.name "你的名字"`、`git config user.email "你的邮箱"`。

**测试报 `path should be a path.relative()'d string`（Nuxt 项目常见）**
原因：任务工作区和项目不在同一个盘符，而工作区里的 `node_modules` 是指向主仓库的链接，Nuxt 算出的依赖路径变成了 `D:\...` 这种绝对路径。0.2.1 起工作区会自动放在项目所在盘符，不再出现。**在这之前创建的任务**（工作区在 `C:\Users\...\.devlane\worktrees`）不会自动迁移：丢弃后重新创建即可。

**测试一直跑不完，只能手动停止**
测试命令要用「会自己结束」的，比如 `npm test`、`npm run typecheck`、`npm run lint`。`npm run dev`、`npm start` 以及带 watch 参数的命令是开发服务器或监听模式，永远不会结束。项目页和测试页看到类似命令会给出提示。运行中随时可以点「停止测试」。

**工作区里缺少 `.env` 之类的文件**
工作区只包含 git 已跟踪的文件，没提交的 `.env`、本地配置不会出现在里面。依赖这些文件才能运行的命令（例如启动服务）会失败，需要的话让 Claude 按 `.env.example` 生成，或手动复制进去。

**测试在工作区里失败，主目录却能过**
常见原因是缺依赖。开启项目的「链接 node_modules」，或让 Claude 先安装依赖（需要放行 `npm install`）。

**服务重启后，运行中的任务呢**
变成「已停止」，点「继续」会接着之前的会话做。

**数据在哪里**
`~/.devlane/`：`state.json`（项目、任务、设置）、`tasks/<id>/log.jsonl`（过程记录）、`worktrees/`（所有任务的工作区）。

**怎么彻底清理**
先在界面里丢弃所有任务（这样会正确删除 git worktree 和分支），再删除 `~/.devlane`。

## 12. 当前限制

- 只支持 Claude Code。
- Jira 客户端尚未对真实站点联调；如果列表加载报错，错误信息会直接显示出来，请把它发给开发者。
- 支持添加多个本地仓库（项目），各自创建任务、各自开 PR。
- **不支持**把单个任务绑定到多个仓库，或一次编排改多个仓。
- 没有多人协作功能；单用户、单机。
- 不会自动合并 PR，也不会改 Jira 状态。

## 13. 在阿里云服务器上使用

服务已部署在 `8.133.179.238`，只监听服务器本机，**必须通过 SSH 隧道访问**：

```powershell
cd d:\dev面板\devlane
.\deploy\tunnel.ps1          # 保持这个窗口开着；Ctrl+C 关闭隧道
# 然后浏览器打开 http://127.0.0.1:7790
```

（这台服务器的 SSH 握手比较慢，隧道要等十几秒才能连上。）

### 让服务器上的 claude 可用

服务器上已装好 Claude Code，但**还没有认证**，直接创建任务会失败并提示 `Not logged in`。二选一：

**方式 A：用和你本机相同的配置。** 你本机的 claude 用的是自定义接口地址加令牌（在 `~/.claude/settings.json` 的 `env` 里）。把同样的变量写进服务器的配置文件：

```sh
ssh -i ~/.ssh/id_ed25519_devlane admin@8.133.179.238
sudo nano /etc/devlane.env      # 取消注释并填写 ANTHROPIC_BASE_URL、ANTHROPIC_AUTH_TOKEN（或 ANTHROPIC_API_KEY）
sudo systemctl restart devlane
```

如果你本机依赖 `HTTP_PROXY / HTTPS_PROXY` 才能访问接口，这里也要加上。令牌我没有替你复制，请自己填。该文件权限是 `root:devlane 640`，只有 root 和 devlane 用户能读。

**方式 B：交互登录。**

```sh
ssh -t -i ~/.ssh/id_ed25519_devlane admin@8.133.179.238
sudo -u devlane -H env HOME=/opt/devlane/home PATH=/opt/devlane/node/bin:/opt/devlane/tools/bin:/usr/bin:/bin claude
# 进入后输入 /login，按提示完成
```

配好后，在「设置」页点「重新检测」，再建一个小任务试试。

### 服务器上的项目

任务在服务器上运行，所以项目也必须在**服务器上**。用 `devlane` 用户把仓库克隆到 `/opt/devlane/home/repos/` 下，再在「项目」页添加这个路径：

```sh
sudo -u devlane -H env HOME=/opt/devlane/home git clone <仓库地址> /opt/devlane/home/repos/<名字>
```

- 服务器没有你的 git 凭据，克隆私有仓库需要先为 `devlane` 用户配置部署密钥或令牌。
- 服务器上**没有 gh**，所以「推送并创建 PR」暂不可用；提交到任务分支可以。需要的话可以再装一份私有的 gh。
- **不要把 `/opt/one-class` 添加为项目**。DevLane 对它不做任何事，但添加后会在它的 `.git` 里记录 worktree 信息。
- 同一时间只跑 1 个任务（服务器内存只有 1.6G，且要留给 one-class）。

### 维护

```sh
sudo systemctl status devlane          # 状态
sudo systemctl restart devlane         # 重启
sudo journalctl -u devlane -n 50       # 日志
ls /opt/devlane/home/.devlane          # 数据：state.json、tasks/、worktrees/
```

升级：本机执行 `.\deploy\deploy.ps1`。卸载：`.\deploy\deploy.ps1 -Uninstall`（保留数据）。

任务列表支持**本地**关键字搜索、标签与优先级筛选，可与项目/状态筛选叠加；这些字段存在本机状态里，与 Jira labels/priority 独立，**不会回写** Jira。
