## 2. 阻塞项：必须由你提供或决定

| 编号 | 缺口 | 为什么阻塞 | 建议默认值（你不回复时我采用） |
| --- | --- | --- | --- |

| B2 | 一个可调用的 Jira 测试站点与凭据 | 没有真实站点，只能用录制夹具测试，无法验证字段映射与流转 | 先用夹具开发；联调前请提供沙盒站点 |

## 3. 设计缺口：文档里没写清、需要补的

这些是我在复盘 `01`~`03` 时发现的，AI 可以自行补充。

1. **Agent 运行时没有定义**。文档写了沙箱里跑 Agent，但没说 Agent 是自研循环，还是封装现成的命令行编码 agent。这是最大的设计空白。建议：MVP 定义一个 `ExecutorAdapter` 接口（`start / send / interrupt / stream`），首个实现封装一个现成的命令行 agent，自研循环放到后面。
2. **模型网关的契约没写**。需要定义请求、流式响应、计量字段、失败重试。
3. **事件 payload 的 JSON Schema 没落地**。`03` 只列了字段名，需要逐类型写成可校验的 schema。本次 M0 实现。
4. **策略规则的配置格式没定**。需要 YAML 格式、优先级与冲突处理。
5. **提示词与流水线模板没有**。缺陷流水线各阶段的系统提示、需求流水线的计划模板都未编写。
6. **鉴权与多用户未细化**。`03` 只写了接入 SSO，MVP 需要一个本地账号方案。
7. **泳道图没有线框稿**。节点密度、配色、图例位置需要设计稿，否则前端会反复返工。
8. **Windows 开发机与 Linux 沙箱的差异**。路径分隔符、换行符、worktree 挂载、文件权限，需要在执行器里统一处理，并写进测试。
9. **Webhook 的可达性**。本机开发时 Jira 无法回调内网地址，需要隧道方案或只用轮询。
10. **Jira 配额与限流细节**。`03` 写了退避重试，但没有给出并发上限、单次批量大小的具体数字，需要联调时实测后确定。
11. **测试数据**。缺少一批覆盖典型情况的 Jira 响应夹具（缺字段、ADF 嵌套、分页、429）。
12. **成本口径**。token 单价表、沙箱时长折算方式未定义。

## 4. 能自动推进与需要人介入的边界

| 类别 | AI 可以自主完成 | 需要你介入 |
| --- | --- | --- |
| 共享包 | 事件 schema、哈希链、ADF 转换、就绪评分 | 无 |
| 后端模块 | 事件服务、状态机、策略引擎、调度器（以内存或 SQLite 先行） | PostgreSQL 实例（生产） |
| Jira 连接器 | 客户端、分页、重试、字段映射、夹具测试 | 真实站点与授权（B1、B2） |
| 执行器 | 本地进程执行器、策略拦截、worktree 管理 | Docker 主机（B5） |
| 前端 | 页面、泳道图组件、会话分组、模拟数据联调 | 视觉评审 |
| 交付 | 本地提交 | 创建远端仓库、推送、开 PR 前的确认 |

## 5. 建议的补充顺序

1. 本次：M0 工程骨架 + 事件 schema + ADF 转换 + 就绪评分，全部带测试。不依赖任何阻塞项。
2. 下一步：事件服务（SQLite 先行）、状态机、策略引擎。
3. 你提供 B1、B2 后：联调 Jira 连接器。
4. 你提供 B4、B5 后：接入模型网关与真实执行器。
5. 前端泳道图：先用模拟事件流做出可交互原型，再接后端。

## 6. 风险提示

- 没有 Docker 时，「沙箱隔离」只能用路径限制和命令拦截实现，强度低于容器。生产环境前必须换成容器或更强的隔离。
- Jira 的接口行为（限流、字段、流转）以真实站点为准，夹具测试通过不等于联调通过。
- 自动执行代码的 agent 面对不可信的 issue 文本，策略引擎是最后一道防线，需要专门的注入测试集。
