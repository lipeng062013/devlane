# DevLane 使用手册

| 项 | 内容 |
| --- | --- |
| 适用版本 | 0.1.0 |
| 访问地址 | http://8.133.179.238:18090 |
| 登录口令 | 本机 `deploy\.devlane-secret.txt`（服务器上同一口令） |

> **先看这个**：当前的执行器是**模拟的**。它按脚本产生提交、测试、门禁等事件，用来演示和验证调度、策略与观测链路，**不会调用模型，也不会修改任何代码或创建真实 PR**。界面右上角的「模拟执行器」标记就是提醒这一点。

## 1. 它做什么

DevLane 把一个需求变成一条「泳道」。泳道由 AI 执行器推进，每一步都记成事件，画在泳道图上。遇到高风险操作时暂停，等你批准。你可以随时暂停、恢复、放弃，或在评审后合并。

```
需求池 ──开泳道──▶ 就绪 ──加入队列──▶ 排队中 ──▶ 运行中 ──▶ 待评审 ──合并──▶ 已合并
                                        │           ▲  │
                                        │           │  └─ 触发门禁 ─▶ 等待批准 ─(批准/拒绝)─┘
                                        └─ 暂停 ◀──▶ 已暂停          任意时刻可「放弃」
```

## 2. 三分钟上手

按下面顺序点一遍，就能看到全部主要功能：

1. 打开地址，输入口令登录。
2. 左侧需求池里有 5 个示例需求。**DL-103（任务）**评分 100，点「开泳道」。
3. 右侧会弹出详情，点「加入队列」。几秒后泳道图上出现节点，一步一步往右长。
4. 约 10 秒后它进入「待评审」，点「合并」。完成。
5. 再对 **DL-102（需求）**重复一遍：它会在中途停在「等待批准」，页面顶部出现红色横幅，说明要修改 `package.json`。点「批准」继续，或点「拒绝」跳过这一步。
6. 再对 **DL-101（缺陷）**重复一遍：在泳道图里找红色节点，点开看，能看到一次「被拒绝」的写入，原因是缺陷流水线在复现阶段只允许改测试文件。
7. DL-104、DL-105 评分很低，「开泳道」是灰的。鼠标放上去能看到还缺什么。

## 3. 界面说明

### 3.1 顶部

- 左侧五个数字：运行中、排队、等待批准、待评审、已合并的泳道数。
- 「模拟执行器」：鼠标放上去显示并发上限。
- 「退出」：清除登录状态。

### 3.2 门禁横幅（红色，仅在有待处理门禁时出现）

每条显示：哪条泳道、门禁类型、原因，以及「批准」「拒绝」按钮。点泳道名可打开详情。

- **批准**：泳道恢复运行，被拦下的那一步放行执行一次。
- **拒绝**：跳过被拦下的那一步，记录一条错误事件，泳道继续往后走。

### 3.3 需求池（左）

每张卡片显示编号、类型、来源（示例 / 手动 / Jira）、标题和**就绪评分**条。

| 评分项 | 分值 | 怎样算满足 |
| --- | --- | --- |
| 验收标准 | 30 | 描述里有「验收标准」「验收条件」或 Acceptance Criteria 标题，或写了「假设…当…则…」 |
| 复现信息 | 30 | **仅缺陷**。描述里要同时出现「复现步骤」「期望」「实际」三类字样 |
| 影响范围 | 20 | 填了「影响模块」，或描述里有「影响范围」字样，或写了文件路径（如 `src/a/b.ts`） |
| 优先级 | 5 | 选了优先级 |
| 截止时间 | 5 | 填了截止日期 |
| 负责人 | 10 | 填了报告人（Jira 导入的需求也可以是经办人） |

非缺陷需求没有「复现信息」这一项，其余项按比例折算成 100 分。**达到 70 分才能开泳道。** 评分不够时卡片上会列出缺哪几项。

**新建需求**：点「新建」，填标题、类型、优先级、截止日期、报告人、影响模块（逗号分隔）和描述。「填入 Bug/Story/Task 模板」按钮会按类型填入一份满足评分要求的描述骨架，照着补内容即可。

**从 Jira 导入**：只有服务器配置了 Jira 连接后才显示（见第 7 节）。

### 3.4 泳道图（中）

- 一行一条泳道。左侧固定显示编号、类型、状态、标题、泳道号和当前阶段，右侧是事件节点，按发生顺序从左到右。
- 水平方向可以滚动；新事件到来时，如果你停在最右边会自动跟随。
- 运行中的泳道末尾有蓝色脉冲点；等待批准的泳道末尾有红色「等待批准」标签。
- 已合并、已放弃的泳道排在最后，颜色变淡。
- 鼠标放在节点上显示事件类型、时间和摘要；点击节点会打开详情并选中该事件。
- 左侧标签里有快捷按钮：就绪时「加入队列」，暂停时「恢复」，待评审时「合并」。

节点颜色：

| 颜色 | 含义 |
| --- | --- |
| 蓝 | 提交 |
| 绿 | 测试通过、评审通过、合并 |
| 红 | 测试失败、错误、被策略拒绝的工具调用 |
| 橙 | 重试、切换模型 |
| 红色菱形 | 门禁开启或处理 |
| 紫 | 产出物（分析、计划、PR 描述） |
| 灰色小点 | 工具调用 |
| 浅灰 | 检查点（分支创建、排队、开始等） |

### 3.5 泳道详情（右）

点泳道行或节点后出现。

- 上部：标题、泳道号、阶段、分支、工作目录、执行器、PR（模拟）。
- 操作按钮：按当前状态显示，见下表。
- **校验哈希链**：重新计算这条泳道所有事件的哈希，确认没有被改动或缺失。显示「哈希链完整，共 N 个事件」为正常。
- 事件列表：序号、类型、摘要、时间。点一行，下方显示该事件的完整内容（事件 id、前一个事件的哈希、载荷、执行者）。

| 当前状态 | 可用操作 |
| --- | --- |
| 就绪 | 加入队列 |
| 排队中 | 暂停 |
| 运行中 | 暂停、放弃 |
| 等待批准 | 批准/拒绝（详情内和顶部横幅都有）、放弃 |
| 已暂停 | 恢复、放弃 |
| 待评审 | 合并、放弃 |
| 已合并 / 已放弃 | 无（终态） |

**放弃不可恢复**，会弹出确认。放弃后，同一个需求可以重新开一条新泳道。

## 4. 规则与行为

- **并发上限 3**：同时最多 3 条泳道处于运行中，多出来的排队，前面的进入评审后自动补位。
- **同一需求同时只能有一条进行中的泳道**。
- **自动更新**：页面通过实时推送刷新，另有每 10 秒一次的兜底刷新，不需要手动刷新页面。
- **重启不丢数据**：服务重启后，运行到一半的泳道从断点继续。
- **策略规则**（模拟执行器会真实触发它们）：
  - 写文件超出泳道工作目录：拒绝。
  - 危险命令（强推、`rm -rf /` 等）：拒绝。
  - 缺陷泳道在复现、红测阶段改非测试文件：拒绝。
  - 改动超出声明范围：需要批准。
  - 改动 `package.json`、锁文件、迁移目录：需要批准。
- **三种流水线**（由需求类型决定）：
  - 缺陷：定位、复现、红测、修复（含一次测试失败后重试）、验证、PR。
  - 需求：计划、实现、测试（含一次失败后换模型）、修改依赖清单（触发门禁）、验证、PR。
  - 任务：定位、实现、验证、PR。

## 5. 常见问题

**「开泳道」是灰的**
评分没到 70。把鼠标放在按钮上，或看卡片上的「缺少…」标签，补齐后重新创建需求。已创建的需求目前不能编辑，需要新建一条。

**泳道一直停在「等待批准」**
这是门禁在等你。看页面顶部红色横幅，点批准或拒绝。

**泳道图不动**
运行中的泳道每 2.5 秒走一步。如果泳道在「排队中」，说明并发已满，等前面的完成。已暂停的泳道不会前进，需要点「恢复」。

**登录提示「尝试次数过多」**
同一地址 5 分钟内输错 10 次会被临时拒绝，等几分钟再试。

**忘了口令**
本机 `deploy\.devlane-secret.txt` 里就是。也可以在服务器上执行 `sudo grep DEVLANE_PASSWORD /etc/devlane.env`。

**合并后会发生什么**
只会在 DevLane 里把泳道标成已合并，并记一条合并事件。不会真的合并任何代码，因为 PR 是模拟的。

## 6. 当前限制

- 执行器是模拟的，不调用模型，不改代码。
- PR 是模拟的（`simulated://pr/编号`），没有对接 GitHub。
- 评审阶段只能「合并」或「放弃」，不能「打回修改」。
- 需求创建后不能编辑或删除。
- 只有一个口令、一个用户（admin）。
- 服务是 HTTP，没有加密。不要在公共网络或共用口令的场景使用。
- 没有对接 Jira 的状态回写。

## 7. 管理员操作

以下在你的 Windows 开发机的项目目录里执行：

```powershell
.\deploy\deploy.ps1                # 升级部署（先测试再打包，失败自动回退）
.\deploy\deploy.ps1 -InspectOnly   # 只读检查服务器
.\deploy\deploy.ps1 -Uninstall     # 卸载，数据保留
```

在服务器上（`ssh -i ~/.ssh/id_ed25519_devlane admin@8.133.179.238`）：

```sh
sudo systemctl status devlane          # 运行状态
sudo systemctl restart devlane         # 重启
sudo journalctl -u devlane -n 50       # 最近日志
sudo cat /etc/devlane.env              # 配置（含口令，注意保密）
ls -la /opt/devlane/data               # 数据：state.json（看板）、events.db（事件）
```

**备份**：停服务后复制 `/opt/devlane/data` 下两个文件即可。

**启用 Jira 导入**：在 `/etc/devlane.env` 末尾追加下面三行，然后 `sudo systemctl restart devlane`。

```
JIRA_BASE_URL=https://house730.atlassian.net
JIRA_EMAIL=你的Jira登录邮箱
JIRA_API_TOKEN=在 Atlassian 账号设置里创建的 API Token
```

可选：`JIRA_ACCEPTANCE_FIELD`（验收标准的自定义字段 id）、`JIRA_DEFAULT_JQL`（导入范围）。配置后需求池标题栏会出现「从 Jira 导入」。注意：该连接器尚未对真实站点联调过，首次使用请先用测试项目。

其他可调参数（并发上限、执行间隔、端口等）见 `README.md` 的环境变量表。
